# kr-claims

## 목적

「건강기능식품의 기준 및 규격」 고시에서 **인정 기능성 문구·일일섭취량·
섭취 시 주의사항**을 꺼내 온다. 논문 근거 팩이 있으면 용량까지 대조한다.

## 불변 원칙

1. **인정 문구는 원문 그대로 옮긴다.** 다듬거나 요약하거나 쪼개지 않는다 —
   한 글자만 달라도 그것은 인정받지 않은 표현이다. 고시가 `･`로 이어
   붙여 놓은 기능성은 이어 붙은 채로 하나다.
2. **이 스킬은 적법성을 판정하지 않는다.** 카피 표현이 인정 범위 안인지는
   의미 판정이라 기계로 못 한다. 문구를 나란히 놓는 데까지가 여기 일이고,
   대조는 사람이 한다.
3. **미등재는 "인정되지 않음"이 아니다.** 데이터는 고시형 원료만 담는다.
   개별인정형(대부분의 신소재)은 별도 문서에 있다.
4. **수치 판정은 LLM이 하지 않는다.** `scripts/check_kr_claims.py`만이 비교한다.

## 실행

경로는 반드시 `${CLAUDE_PLUGIN_ROOT}` 기준으로 쓴다.

### 조회 모드 — 팩이 없을 때

성분의 인정 문구·섭취량·주의사항만 필요한 경우.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_kr_claims.py" \
  --claims "${CLAUDE_PLUGIN_ROOT}/data/kr_claims.json" \
  --ingredient "오메가3" --output kr-report.json
```

### 대조 모드 — evidence-pack이 있을 때

논문 용량을 국내 인정 범위와 비교한다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_kr_claims.py" \
  --pack evidence-pack.json \
  --claims "${CLAUDE_PLUGIN_ROOT}/data/kr_claims.json" \
  --output kr-report.json
```

`--ingredient`를 생략하면 팩의 `topic`("마그네슘 × 수면")에서 앞부분을 쓴다.
원료명이 팩과 다르게 등재돼 있으면(예: "EPA 및 DHA 함유 유지") 직접 지정한다.

| 종료 코드 | 뜻 |
|---|---|
| 0 | 등재 확인 + 용량 비교 성공 + 상한 초과 없음 (조회 모드는 항상 0) |
| 2 | **발행 전 확인 필요** — 미등재 / 상한 초과 / 비교 불가 |

## 출력 해석 — 여기서 가장 많이 틀린다

리포트를 사용자에게 표로 옮길 때 아래를 지킨다.

| 상태 | 뜻 | 어떻게 전달하나 |
|---|---|---|
| `within` | 인정 범위 안 | basis를 함께 적는다 |
| `above` | **인정 상한 초과** | 맨 위 경고. 그 수치를 국내 콘텐츠에 인용하지 말 것 |
| `below` | 인정 최소치 미만 | 다른 기능성 기준이면 정상이다. 단정하지 마라 |
| `incomparable` | 비교 불가 | 사유를 그대로 적는다. "문제없음"이 아니다 |

**`basis`가 있으면 반드시 함께 보여준다.** "EPA와 DHA의 합으로서 0.5~2 g"인데
논문이 EPA 단독 용량을 썼다면 두 숫자는 애초에 비교 대상이 아니다.
스크립트는 단위만 맞으면 비교하므로, 기준 성분이 같은지는 사람이 봐야 한다.

**`found: false`일 때 "국내 미인정"이라고 쓰지 마라.** 정확한 문장은
"이 고시(고시형)에 없음 — 개별인정형 목록 확인 필요"다.

## 출력 형식

```
| 인정 기능성 문구 | 일일섭취량 | 논문 용량 | 판정 |
|---|---|---|---|
| 혈중 중성지질 개선 ･ 혈행 개선에 도움을 줄 수 있음 | EPA와 DHA의 합으로서 0.5 ~ 2 g | 500 mg | ✅ 범위 내 |
| 기억력 개선에 도움을 줄 수 있음 | EPA와 DHA의 합으로서 0.9 ~ 2 g | 500 mg | 최소치 미만 |
```

표 아래에 **섭취 시 주의사항**을 그대로 옮긴다. 이것이 안전 문구의 1차 근거다.
초록에 부작용 언급이 없다는 것과 혼동하지 마라 — 미언급은 안전이 아니다.

리포트의 `warnings`는 빠짐없이 전달한다.

## 데이터 신선도

`data/kr_claims.json`은 **플러그인에 동봉된 스냅샷**이다. 고시는 개정되고,
개정 때마다 일일섭취량이 바뀌는 원료가 나온다.

- 기준 고시 번호·시행일·추출 확인일이 리포트의 `warnings`에 실린다.
  맨 앞에 있다고 가정하지 말고 `warnings`를 통째로 그대로 전달한다.
- 스크립트가 데이터가 오래됐다고 경고하면 **그 경고를 사용자에게 올린다.**
  갱신은 플러그인 재배포가 필요하다 (`README.md`의 빌드 절차).

## 하지 않는 것

- 카피 문구 작성·수정
- 적법성 판정 (사전 자율심의를 대신하지 않는다)
- 개별인정형 원료 조회 — 데이터에 없다
- 표시·광고 사전심의, 품목제조신고 확인 등 제품 단위 절차
