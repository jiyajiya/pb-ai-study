오프닝우리가 푸는 문제

진짜 문제는 시간이 아니라 그럴듯한 숫자다

카드뉴스 한 장 만들려면 논문 찾고, 숫자 뽑고, 다시 확인하는 데 30분. 그런데 그보다 무서운 건 따로 있습니다.

겉으로 보이는 문제

시간이 오래 걸린다PubMed 검색 → 초록 읽기 → 용량·기간 정리 → 출처 다시 확인. 콘텐츠 한 편에 30분.

진짜 문제

AI가 숫자를 지어낸다"마그네슘 500mg, 수면 시간 23% 개선" — 문장은 완벽한데 그 논문엔 그런 숫자가 없다.

약사에게 이건 치명적입니다. 오탈자는 수정하면 되지만, 없는 숫자를 근거처럼 발행하면 그건 잘못된 복약 정보가 됩니다. 그래서 이 도구의 목표는 "빠르게"가 아니라 "틀린 숫자는 절대 안 나오게"입니다.
한 줄 그림 — AI를 더 똑똑하게 만드는 게 아니라, AI가 틀려도 그 틀린 값이 밖으로 못 나가는 구조를 만든다.
발표자 노트

여러분, 챗GPT한테 "마그네슘이 수면에 좋다는 논문 근거 좀 줘" 해보신 적 있죠? 논문 제목도 나오고 숫자도 나와요. 근데 그 PMID로 들어가 보면 그런 숫자가 없는 경우가 있습니다.

  • 여기서 청중 반응 확인. 경험 있는 분 손 들어보게 하면 몰입도가 확 올라감.
  • "AI가 거짓말을 한다"가 아니라 "AI는 그럴듯한 다음 단어를 고르는 기계라 빈칸을 자연스럽게 메운다"로 설명할 것.
  • 이 세션의 결론 미리 던지기: 프롬프트로 "지어내지 마"라고 백 번 써도 안 막힌다. 구조로 막아야 한다.

개념오늘의 핵심 개념

서브에이전트 — 일 나누기가 아니라 책상 나누기

이 개념 하나만 제대로 잡으면 나머지 코드는 전부 자연스럽게 읽힙니다. 오늘 배울 것 중 유일하게 다른 업무에도 그대로 쓰이는 개념입니다.

먼저, 컨텍스트(context)란
AI가 지금 이 대화에서 "보고 있는 것 전부"를 올려둔 책상
지금까지 주고받은 말, 읽은 파일, 검색 결과가 전부 이 책상 위에 쌓입니다. AI는 책상 위에 있는 것만 보고 답합니다. 그리고 책상은 크기가 정해져 있고, 한번 올라온 건 잘 안 내려갑니다.
비유 — 조제대 위. 지금 조제 중인 처방전 옆에 아까 다른 환자 약봉지가 놓여 있으면? 그게 사고의 시작입니다.
서브에이전트 = 별도 책상을 가진 조수
본인만의 새 책상에서 일하고, 정해진 형식의 결과 한 장만 건네주고 책상을 통째로 버리는 AI
조수가 논문 30편을 다 펼쳐놓고 읽어도, 나에게 오는 건 "결론: T2, 볼 논문 8개"라는 쪽지 한 장뿐. 30편의 초록은 조수 책상과 함께 사라집니다.

정정메인 책상에 초록 원문이 아예 안 올라오는 게 아닙니다. 조수 2(miner)가 돌려주는 quote는 글자 하나 안 바꾼 원문 문장이고, 그건 메인 책상에 올라옵니다. 그리고 그건 버그가 아니라 요구사항입니다 — 나중에 스크립트가 대조할 대상이 없으면 검증 자체가 성립하지 않으니까요.

바뀌는 것은 차단이냐 아니냐가 아니라 양과 형태입니다.

발표자 노트

이 슬라이드가 오늘 발표의 심장입니다. 여기서 20분 써도 아깝지 않습니다.

회사에서 일 나눌 때 "네가 이거 잘하니까 맡아" 하잖아요. AI 서브에이전트는 좀 다릅니다. 잘해서 맡기는 게 아니라, 내 책상에 뭐가 올라올지를 내가 고르려고 맡기는 거예요.

  • 조제대 비유를 실제 몸짓으로 하세요. 책상 위에 뭘 올리고 치우는 동작.
  • "정정" 박스를 건너뛰지 마세요. 예전 버전에서 "원문이 아예 안 올라온다"고 설명했는데 그건 과장입니다. 정확히 말하면 양이 줄고 출처에 묶인다입니다. 청중이 나중에 실습에서 quote를 눈으로 보게 되므로, 여기서 미리 정직하게 짚어야 신뢰가 유지됩니다.
  • 흔한 오해 정정: "서브에이전트를 쓰면 더 똑똑해지나요?" → 아니오. 덜 헷갈리고, 검사가 가능해질 뿐입니다.
  • 질문 유도: "그럼 조수한테 논문 8개를 한꺼번에 주면 어떻게 될까요?" → 다시 섞임. 그래서 1편에 1명.

왜 P3-1(파일 저장)이 따로 있나

파이썬 스크립트는 대화 내용을 볼 수 없습니다. 파일만 읽습니다. 그래서 조수 결과를 파일로 떨궈야 검증이 시작됩니다. 그리고 이 중간 지점이 "AI가 만든 것"과 "기계가 검사하는 것"의 경계선입니다.

여기서 값을 고치면 안 됩니다. 오타처럼 보여도, 단위가 어색해 보여도 그대로 저장합니다. 다듬는 순간 "AI가 준 값"이 아니라 "사람이 손댄 값"이 되고, 검사는 통과하지만 아무것도 보증하지 못하는 숫자가 됩니다.

조수 1 — 판정하고 고른다. 숫자는 안 뽑는다

"근거중심의학 훈련을 받은 DI 담당 약사"라는 역할이 주어진 조수. 논문 30~40편을 훑고 쪽지 한 장만 돌려줍니다.

검색을 4번 나눠 던진다 — 각각 목적이 다름
회차필터이걸로 알아내는 것
1차메타분석 / 체계적 문헌고찰만상위 근거가 있는가 → T1 판정의 열쇠
2차사람 대상 RCT만숫자를 뽑을 논문 확보
3차필터 없음 (사람 대상만)인체 연구가 아예 없는지 → T3 신호
4차가이드라인 문서만학회 가이드라인이 있는가 → guideline_hit

1차가 0건이면 T1은 불가능. 2차가 0건이고 3차에 동물·시험관만 있으면 T3. 검색 설계 자체가 판정 로직입니다.

4차를 건너뛰면 근거가 아무리 강해도 T1이 안 나옵니다. T1의 조건이 "상위 근거 + 가이드라인"인데, 가이드라인 여부를 안 물어봤으니 영원히 T2에 갇힙니다. 회귀 테스트 F1(오메가3)이 이걸 잡는 케이스입니다.
4차에서 나온 논문은 숫자 채굴 대상이 아닙니다. 가이드라인 문서에는 원 시험의 효과 크기가 없으니까요. "있는지 없는지"만 봅니다.
성분 일치 검사 (off-target) — 실무에서 제일 많이 터지는 문제
"EPA"로 검색하면 크릴오일·EPA+DHA 복합제·ALA 비교 시험이 함께 딸려 옵니다

off_target으로 찍히면어떻게 되나
목록에는남습니다 (몇 편이 걸렀는지 보여야 하니까)

톤 판정 규칙 — 위에서부터 걸리는 첫 번째를 채택

R4. positive가 대부분 하위집단 한정 OR 혼재  → T2
R5. 어디에도 해당 없음  → T2 (보수적 기본값)

// 원문: "decreased sleep onset latency by 17.36 min (P = 0.02)"

✅ value: "17.36"  unit: "min"   ← 둘 다 quote에서 잘라낸 그대로

❌ value: "17"                   ← 반올림 금지
❌ value: "약 30% 단축"           ← 계산 금지
단위를 지어내는 것이 값을 지어내는 것보다 위험합니다. 값은 검증을 통과하는데 단위만 틀리면, 카드에는 "17.36시간"이 찍힙니다. 검사를 통과한 틀린 숫자 — 제일 잡기 어려운 종류입니다.

p값은 버리지 않고 significance 칸에 따로 담습니다. 단, 효과 크기 문장과 같은 문장에 있는 p값만. 다른 문장에서 끌어오면 다른 지표의 p값이 붙습니다.

지금까지는 전부 "이렇게 해줘"였습니다. 여기서부터는 "이렇게 된다"입니다. 파이썬 코드는 기분도 없고 아부도 안 합니다.

검증 계약 5개 — 전부 통과해야 verified: true
C1quote가 PubMed 초록 원문 안에 실제로 있고, 문장이 하나뿐인가 — 스크립트가 초록을 직접 다시 받아와서 대조. 조수가 인용문을 지어내면 통과 불가
C2value가 그 quote 안에 있는가 — 인용문은 진짜인데 숫자만 바꿔치기한 경우를 잡음
C3(effect 한정) 그 값이 효과 크기의 형태인가 — 원문에 실재하지만 효과 크기가 아닌 것(p < 0.05)을 걸러냄
C4unit이 그 quote 안에 있는가 — 17.36 + hours처럼 단위만 바꾼 60배 뻥튀기를 잡음
C5(conclusion 한정) quote만 검사 — 이 슬롯엔 value·unit이 없어서 C2~C4가 아예 적용되지 않습니다
C1의 "문장이 하나뿐인가"는 이번에 새로 추가된 조건입니다. 없으면 두 문장을 이어붙인 인용문 하나로 뒤의 검사를 속일 수 있습니다 — "Subjects received 500 mg magnesium daily. Sleep onset latency decreased by 17.36 min."을 통째로 quote로 삼으면, value: "17.36"과 unit: "mg"이 둘 다 이 긴 인용문 안에 있다는 이유만으로 C2·C4를 통과했을 겁니다. 실제로는 17.36은 수면 문장의 값이고 mg은 용량 문장의 단위라 서로 아무 관계가 없습니다. 문장을 하나로 제한하면 이런 조합 자체가 만들어지지 않습니다.
C3가 왜 따로 필요한가 — "p < 0.05"는 초록에 진짜로 있는 문자열이라 C1·C2를 멀쩡히 통과합니다. 프롬프트 규칙만으로는 새어 나오기 때문에 정규식으로 한 겹 더 막습니다. 규칙은 간단합니다 — 숫자 칸(value)에는 숫자만 들어갑니다. 단위·지표명·p값은 각자 칸이 따로 있습니다. 그 칸에 숫자 하나가 아닌 게 들어오면 그 자리에서 폐기됩니다.
C4가 왜 따로 필요한가 — 값과 단위를 따로 받는 구조라서 그렇습니다. 값만 검사하면 단위 칸은 무방비입니다. 그리고 카드에 찍히는 건 둘의 합입니다.
핵심 로직(단순화) — 통과 못 하면 값을 지웁니다
# C1: 인용문이 초록에 실재하고, 문장이 하나뿐인가
if quote_norm not in abstract_norm or not is_single_sentence(quote_norm):
    return {"value": None, "verified": False,
            "reason": "quote_not_in_abstract"}

# C2: 값이 인용문 안에 "숫자로서" 실재하는가 — 단순 부분문자열 검사가 아니다.
# 실제 코드는 value_in_quote(value, quote)로 수 경계까지 본다.
if not value_in_quote(value_norm, quote_norm):
    return {"value": None, "verified": False,
            "reason": "value_not_in_quote"}

# C3: effect 슬롯만 — 숫자 하나 형태가 아니면 폐기 (단위·지표명·p값은 이미 다른 칸)
if slot_name == "effect":
    reason = effect_shape_reason(value_norm)   # 숫자 하나 형태인지만 검사

# C4: 단위도 인용문 안에 "낱말로" 실재하는가

if unit and not re.search(rf"(?<![a-z]){re.escape(normalize(unit))}(?![a-z])", quote_norm):
    return {"value": None, "verified": False,

핵심은 "value": None입니다. "의심스러움" 표시를 다는 게 아니라 값을 실제로 지워버립니다. 팩에 남아 있으면 누군가는 결국 씁니다.

C2가 막는 건 "숫자 바꿔치기"입니다. 초록이 "-0.34 mmol/L"이라고 썼는데 조수가 부호를 빼고 value: "0.34"로 냈다고 합시다. "0.34"라는 글자 자체는 quote 안에 있으니 단순 부분문자열 검사로는 통과해버립니다. 수 경계 검사는 앞뒤로 숫자·부호·소수점이 더 이어지지 않는지까지 봐서 이걸 잡습니다. 같은 원리로 17.36을 17로 반올림하거나, 천단위 쉼표를 붙이거나 빼거나, %를 잘라내도 통과하지 못합니다 — 전부 일부러 추가한 방어입니다.
C4에서 "그냥 들어 있는지"가 아니라 "낱말로 들어 있는지"를 봅니다. 그러지 않으면 magnesium의 g 한 글자에 단위 g가 걸려서, 500 mg가 500 g(1000배)으로 통과합니다. C4가 막으려던 바로 그 사고가 C4를 뚫는 셈입니다.
