# pubmed-evidence

성분 × 효능 조합의 PubMed 근거를 수집해 `evidence-pack.json`을 만든다.
**숫자 환각을 스크립트 게이트로 차단하는 것**이 이 플러그인의 존재 이유다.
카피도 카드도 만들지 않는다 — 산출물은 인용문·PMID·무결성 정보가 붙은
검증 결과 레코드이고, 문안은 하류(`ingredient-analysis`)가 쓴다.

## 이 저장소에서만 쓰는 말

아래는 전부 **이 플러그인이 스스로 정한 내부 용어**다. 근거중심의학이나
업계의 표준 용어가 아니므로, 바깥 사람과 대화할 때 그대로 쓰면 통하지 않는다.

### 톤 — T1 / T2 / T3

`evidence-scout`이 근거 지형을 훑고 내리는 판정. **콘텐츠를 어떤 형식으로
쓸지 고르는 라우팅 값**이다.

| 값 | 실제 뜻 | 카드뉴스 방향 |
|---|---|---|
| `T1` | 메타분석/SR이 positive **이고** 학회 가이드라인이 존재 | 설명형. 단, 안전성 슬라이드 필수 |
| `T2` | 조건부 — 하위집단 한정이거나 결과가 혼재. **판정 불가일 때의 기본값이기도 하다** | 조건형. 근거→조건→반론 3장 세트 |
| `T3` | 근거가 약하거나 부정이 우세. 인체 RCT가 0편인 경우 포함 | 정정형. 통념→실제→대안 |

> ⚠️ **`T1`은 "1등급"이 아니다.** 숫자가 작을수록 좋다는 뜻으로 읽히지만,
> 실제로 재는 것은 근거의 질이 아니라 "설명형으로 써도 되는 상태인가"다.
> 판정 규칙 R1이 가이드라인 존재를 필수 조건으로 걸기 때문에, **근거가
> 아무리 강해도 학회 가이드라인이 없으면 T2에 갇힌다.** GRADE의 High와는
> 다른 물건이다.

근거의 질 자체를 나타내는 표준 체계는 따로 있다 — GRADE(High/Moderate/Low/
Very low), Oxford CEBM(Level 1~5), USPSTF(A~D, I), 국내 건기식 기능성 등급
(질병발생위험감소 / 생리활성 1·2·3등급). 팩은 이 중 어느 것도 산출하지 않는다.

### 파이프라인 단계 번호 — P1 ~ P8

전체 구상의 단계 번호다. **MVP는 이 중 넷만 구현했고, 번호는 그대로 둔다** —
빈 번호가 "아직 없는 것"을 눈에 보이게 하려고 당겨 쓰지 않았다.

| 번호 | 하는 일 | 상태 |
|---|---|---|
| `P1` | 정규화 — 한글 성분·증상을 영문 학술용어와 MeSH로 | 구현 (메인이 직접) |
| `P2` | 근거 스캔 — 지형 파악, 톤 판정, PMID 선별 | 구현 (`evidence-scout`) |
| `P3` | 숫자 채굴 — 초록 1편 → 5슬롯 | 구현 (`abstract-miner` 병렬) |
| `P3-1` | 중간 산출물 저장 — `raw_slots.json` · `meta.json` | 구현 (P6이 파일로 읽으므로 필수) |
| `P4` | 반론 논문 수집 | 미구현 |
| `P5` | 안전성 추출 | 미구현 (초록에 부작용 언급이 없는 것은 "안전"이 아니라서) |
| `P6` | 검증 — 스크립트 게이트 | 구현 (`verify_evidence.py`) |
| `P6-1` | 식약처 고시 대조 | 구현 (별도 플러그인 `kr-claims`. 미설치면 건너뛴다) |
| `P7` | 카피 작성 | 미구현 (하류 `ingredient-analysis` 몫) |
| `P8` | **광고법 검사** | 미구현 — 없으므로 출력물을 그대로 발행하면 안 된다 |

### 판정 규칙 번호 — R1~R5 · C1~C5

둘 다 "몇 번 규칙에 걸렸는지"를 로그에 남기려고 붙인 번호다. 판정 결과에
`R4: RCT 5편 중 3편 positive이나 모두 결핍군 한정`처럼 따라붙는다.

| 접두어 | 어디에 있나 | 무엇을 정하나 |
|---|---|---|
| `R1`~`R5` | `agents/evidence-scout.md` | 톤. **순서대로 적용해 처음 걸리는 것을 채택**한다. R5는 아무 데도 안 걸렸을 때의 보수적 기본값(T2) |
| `C1`~`C5` | `scripts/verify_evidence.py` | 슬롯 검증. 하나라도 실패하면 그 슬롯은 폐기되고 `null`이 된다 |

`C1` quote가 초록 원문에 그대로 있고 단일 문장인가 · `C1b` quote가 초록에서
문장 **시작** 위치에 놓여 있는가(앞을 잘라 부정어를 뗀 인용을 막는다) ·
`C2` value가 quote 안에 있는가(숫자는 수 경계까지) · `C3` effect의 value가
숫자 하나인가 · `C4` unit이 quote 안에 있는가 · `C5` conclusion 슬롯 한정 —
quote만 검사한다(C1·C1b를 적용).

### 그 밖의 내부 용어

| 말 | 뜻 |
|---|---|
| **슬롯** | 초록에서 뽑는 **고정된 5개 항목** — 효과크기 / 용량·기간 / 대상조건 / 제형·세부 / 저자결론. 이 5개 밖은 뽑지 않는다 |
| **게이트** | LLM이 아니라 **스크립트가 내리는 통과/폐기 판정**. 판정 근거가 매번 같아야 하는 일을 모델에서 뺀 지점을 가리킨다 |
| **팩** (`evidence-pack.json`) | P6의 산출물. 검증된 슬롯 + 인용문 + PMID + 무결성 정보 + `warnings` + `verdict` 한 덩어리 |
| **`verdict`** | `pass`/`review`/`block`. 산문 경고 대신 호출자가 분기에 쓰는 필드. 두 게이트(`pubmed-evidence`·`kr-claims`)가 같은 형태로 답한다. **"발행해도 되는가"가 아니다** |
| **quote** | 초록에서 **글자 하나 안 바꾸고 복사한 한 문장.** 요약도 번역도 아니다. 게이트가 대조할 기준이라 이게 없으면 검증이 성립하지 않는다 |
| **표면 축소** | 서브에이전트를 쓰는 이유. 원문을 메인이 **못 보게** 하는 게 아니라(quote는 들어온다), 메인이 보는 원문을 **검증 가능한 최소 단위로 줄이는** 것 |
| **무결성 정보** | 숫자 말고 논문 자체의 상태 — 철회 여부, 정오표·우려 표명, 이해충돌 진술 원문, 발행연도, 저널, 초록 해시 |
| **`off_target`** | 검색에는 걸렸지만 **개입 성분이 다른** 논문. EPA로 검색했는데 크릴오일 시험이 나온 경우. 톤 판정에서도 채굴 대상에서도 뺀다 |
| **하위 분해** (`needs_decomposition`) | 성분 이름이 너무 넓어 그 단위로는 유효한 근거가 안 나오는 상태. "유산균" → 균주명, "마그네슘" → 염 형태. `true`면 P2에서 멈추고 사용자에게 묻는다 |
| **조회 모드 / 대조 모드** | 하류 `kr-claims`의 두 동작. 인정 문구를 꺼내오는 쪽과, 팩의 용량을 고시와 맞춰보는 쪽(`--pack`) |
| **`kr_notice_name`** | **식약처 고시 등재명.** PubMed 검색어와 다른 축이다 — "오메가3"로 검색하지만 등재명은 "EPA 및 DHA 함유 유지"다. P1이 `normalize.md`에서 옮겨 `meta.json` → 팩까지 내려보내고 P6-1이 쓴다. **`""`(공란)은 "고시형에 없음을 확인했다", `null`은 "확인하지 않았다"** |

### 반대로, 이건 표준 용어다

`PMID`(PubMed 문헌 고유번호), `MeSH`(NLM 표준 주제어), RCT·메타분석·SR,
`esearch`/`efetch`(NCBI E-utilities API), 철회(retraction)·정오표(erratum)·
우려 표명(expression of concern), 이해충돌(COI). 이 말들은 바깥에서도 그대로 쓴다.

## 구조

```
pubmed-evidence/                          ← 플러그인 루트
├── .claude-plugin/
│   ├── plugin.json                     ← 플러그인 매니페스트
│   └── marketplace.json                ← 로컬 설치용 마켓플레이스 등록
├── skills/
│   └── pubmed-evidence/
│       ├── SKILL.md                    ← 오케스트레이터 (메인 컨텍스트)
│       ├── references/
│       │   └── normalize.md            ← 한글↔영문 성분명 매핑 (필요시 로드)
│       └── tests/
│           └── fixtures.md             ← 회귀 테스트 4종
├── agents/
│   ├── evidence-scout.md               ← 서브에이전트 (격리 컨텍스트)
│   └── abstract-miner.md               ← 서브에이전트 (격리 컨텍스트, 병렬)
├── scripts/
│   ├── verify_evidence.py              ← 결정론적 검증 게이트 (LLM 아님)
│   ├── test_verify_evidence.py         ← 네트워크 없이 도는 계약 검사
│   └── sync_workshop.py                ← 워크숍 HTML의 파일 사본 갱신·검사
├── pubmed-evidence-study.html          ← 스터디 자료 (약사·개발자 통합본)
└── pubmed-evidence-workshop.html       ← 실습본 (위 파일들의 사본을 품고 있다)
```

`pubmed-evidence-workshop.html`은 실습에서 참가자가 붙여넣을 파일을 **세 군데**
들고 있다 — `#src-*` 스냅샷, 카드의 줄 수 라벨, 다운로드용 starter zip. 손으로
옮기면 어긋나고, 어긋난 실습본은 원본이 고친 버그를 그대로 재현한다.

```bash
python3 scripts/sync_workshop.py           # 원본에서 다시 채운다
python3 scripts/sync_workshop.py --check   # 어긋나 있으면 종료 코드 1
```

`--check`는 **사람이 기억해서 돌리는 검사가 아니다** — `test_verify_evidence.py`
끝에서 자동으로 돈다. 원본을 고치고 스냅샷을 안 갱신하면 테스트가 실패하고,
저장소 루트의 `.github/workflows/tests.yml`이 push·PR마다 같은 테스트를 돌린다.
로컬에서 잊어도 CI에서 잡힌다.

HTML은 플러그인 동작과 무관한 스터디 자료지만, 플러그인 루트에 있으므로
설치하면 함께 딸려 온다.

### 왜 이 배치인가

| 위치 | 이유 |
|---|---|
| `agents/`가 플러그인 **루트** | 스킬 폴더 하위는 서브에이전트 스캔 대상이 아니다. 루트에 둬야 등록된다 |
| `scripts/`가 플러그인 **루트** | `${CLAUDE_PLUGIN_ROOT}`로 참조. 스킬 안에 두면 경로가 지저분해진다 |
| `references/`, `tests/`가 **스킬 안** | 스킬 본문에서만 쓰는 부속 문서. 필요할 때만 읽힌다 |
| `.claude-plugin/`에 매니페스트만 | 다른 디렉토리를 여기 넣으면 **에러 없이 조용히 무시된다** |

## 컨텍스트 흐름

```
[메인 컨텍스트]                    [격리 컨텍스트]
                                   
SKILL.md 로드
  │
  ├─ P1 정규화 (직접)
  │
  ├─ P2 위임 ────────────────────▶ evidence-scout
  │                                  · 검색 4회 × 최대 40건 스캔
  │                                  · 초록 원문이 여기 쌓임
  │   ◀──── JSON 요약만 반환 ────    · 종료 시 전부 폐기
  │        {tone, pmids}
  │
  ├─ P3 위임 (병렬) ─────────────▶ abstract-miner ×N
  │                                  · 각자 초록 1편
  │   ◀──── 5슬롯 + quote ────────   · 서로 격리 → 숫자 교차오염 없음
  │
  └─ P6 Bash 실행 ───────────────▶ verify_evidence.py
      ◀──── evidence-pack.json ──    · PubMed 재조회 후 대조
                                     · 철회·이해충돌도 같은 응답에서 확인
                                     · LLM 판단 개입 없음
```

### 이 구조가 실제로 하는 일 — 오염 "차단"이 아니라 **표면 축소**

정확히 말하면, 메인 컨텍스트에 초록 원문이 안 들어오는 게 아니다.
miner가 돌려주는 `quote`는 **글자 하나 안 바꾼 원문 문장**이고, 그건
메인 컨텍스트에 들어온다. 위 그림의 `◀── 5슬롯 + quote ──`가 그것이다.

바뀌는 것은 **양과 형태**다.

| | 서브에이전트 없이 | 이 구조 |
|---|---|---|
| 메인에 들어오는 원문 | 스캔한 초록 전문 (검색 4회 × 최대 40건) | 논문당 최대 5문장 |
| 그 문장의 출처 | 섞여 있음 | 슬롯·PMID에 묶여 있음 |
| 검증 가능성 | 불가 (무엇을 대조할지 모름) | 가능 (quote 단위로 대조) |

**quote가 메인에 들어오는 것은 부작용이 아니라 요구사항이다.** P6이
대조할 대상이 없으면 검증 자체가 성립하지 않는다. 서브에이전트를 쓰는
실질적 이유는 원문을 못 보게 하는 게 아니라, 메인이 보는 원문을
**검증 가능한 최소 단위로 줄이는 것**이다.

그리고 숫자의 최종 판정은 어느 쪽이든 LLM이 하지 않는다 — `verify_evidence.py`가
PubMed를 재조회해 대조한다. 컨텍스트 격리는 그 검증을 **가능하게 만드는
설계**이지, 그 자체가 안전장치는 아니다.

## 설치

### 방법 A — 로컬 마켓플레이스로 설치 (개발 중 권장)

`claude plugin install`은 **마켓플레이스에서만** 설치한다. 로컬 경로를
직접 넘길 수 없으므로, 마켓플레이스를 먼저 등록한다.

```bash
claude plugin marketplace add /절대/경로/pharmacist
claude plugin install pubmed-evidence@pharma-bros
claude plugin install kr-claims@pharma-bros        # 국내 기준 대조까지 할 때
```

`marketplace add`에 넘기는 경로는 레포 루트가 아니라
**`.claude-plugin/marketplace.json`이 있는 디렉토리**다. 이 레포에는 그런 곳이
둘이다 — 두 플러그인을 함께 등록하는 `pharmacist/`와, 이 플러그인 하나만
등록하는 `pharmacist/pubmed-evidence/`. 위처럼 `pharmacist/`를 쓰는 것을 기본으로
한다. 이걸 단독으로 떼어 쓸 때만 아래를 쓴다.

```bash
claude plugin marketplace add /절대/경로/pharmacist/pubmed-evidence
claude plugin install pubmed-evidence@pubmed-evidence
```

**둘을 다 등록하지는 마라.** 같은 플러그인이 두 마켓플레이스에 잡혀
어느 쪽 사본이 설치됐는지 추적하기 어려워진다.
매니페스트가 유효한지는 설치 전에 확인할 수 있다:

```bash
claude plugin validate .
```

### 방법 B — 플러그인 안 쓰고 흩어놓기 (빠른 테스트)

```bash
mkdir -p ~/.claude/skills/pubmed-evidence ~/.claude/agents
cp -r skills/pubmed-evidence/* ~/.claude/skills/pubmed-evidence/
cp agents/*.md               ~/.claude/agents/
cp -r scripts                ~/.claude/skills/pubmed-evidence/
# 이 경우 SKILL.md의 ${CLAUDE_PLUGIN_ROOT}를 실제 경로로 바꿔야 한다
```

방법 B는 팀 공유가 안 되고 경로 수정이 필요하다. 혼자 테스트할 때만.


`export`는 **그 터미널 세션에서만** 유효하다. **같은 셸에서 `claude`를 실행**해야
키가 전달된다 — 다른 창에서 세션을 켜면 키 없이 돌다가 병렬 8개에서 429가 나고,
그 실패는 "조회 실패"로 조용히 팩 경고에 묻힌다. 매번 다시 치기 싫으면
`~/.zshrc`에 영구 등록해둔다.

## 게이트가 보증하는 것과 보증하지 못하는 것

| | 막는다 | 못 막는다 |
|---|---|---|
| **조작** | 초록에 없는 숫자·단위를 만들어내기 (C1~C4) | — |
| **의미 반전** | 문장 앞을 잘라 부정어를 떼어낸 인용 (C1b) | 저자가 완충 표현으로 쓴 것을 카피가 단정형으로 옮기는 것 |
| **오배치** | — | 같은 문장의 **다른** 숫자를 잘못된 슬롯에 넣기 |
| **철회 논문** | 철회된 논문은 슬롯이 전부 통과해도 팩에서 뺀다 | 팩 생성 이후에 일어난 철회 |
| **정오표·우려 표명** | 붙어 있다는 사실을 `warnings`에 올린다 | — 제외하지 않는다. 수치가 정정 대상인지는 사람이 원문에서 본다 |
| **이해충돌** | 진술 원문을 팩에 싣는다 | 진술이 없는 논문의 실제 후원 관계 |

**오배치**가 "**같은 문장의** 다른 숫자"로 한정되는 이유: C1이 quote를 단일
문장으로 강제하기 때문이다. 두 문장짜리 quote는 그 자체로 폐기되므로
(`quote_multiple_sentences`), 오배치가 일어날 수 있는 범위는 항상 quote
문장 하나 안이다.

> **단, 이 보증은 문장 경계 검사가 정확한 만큼만 참이다.** 그리고 이 자리는
> 두 번 뚫렸다.
>
> | 정규식 | 놓친 것 |
> |---|---|
> | `[.!?]\s+[A-Z(]` | 숫자 시작 — `"…500 mg daily. 17.36 min was…"` → `17.36 mg` |
> | `[.!?]\s+[A-Z(0-9]` | 그리스문자·소문자 — `"…12 weeks. α-Tocopherol rose by…"` |
>
> 두 번 다 **허용 목록을 늘리는 방식**이 원인이었다. 하필 이 도메인이라
> 더 나빴다 — α-토코페롤·β-글루칸·ω-3는 고시 등재명이고 영문 초록에서
> 문장 첫머리에 온다. 지금은 `[.!?]\s+\S`로 **닫아** 두었다. C3에서 차감식을
> 버리고 "숫자 하나"라는 닫힌 형태로 뒤집은 것과 같은 교훈인데, 여기에는
> 적용하지 않고 있었다.
>
> 대가는 있다. `ABBREV_TAIL`에 없는 약어(`i.v.`, `p.o.`, `approx.`)가 이제
> 경계로 오인돼 **멀쩡한 단일 문장이 폐기된다.** 값이 새는 쪽이 아니라 값을
> 잃는 쪽이라 감수한다. 목록을 넓혀 되살리면 그때마다 진짜 경계도 같이 숨는다.
>
> 남는 교훈은 이것이다 — **위 표의 "막는다" 칸은 정규식 하나에 얹혀 있다.**
> 그래서 회귀 테스트가 게이트의 일부다 (`test_verify_evidence.py`의 R1이
> 같은 문장 쌍의 첫 글자만 바꿔 9종을 고정한다).

```
quote = "Dose was 500 mg daily and triglycerides fell 0.3 mmol/L."
effect = { value: "500", unit: "mg" }     ← 용량인데 효과 크기 자리
→ verified: true
```

`500`도 `mg`도 quote 안에 있고 그 quote는 초록에 있으므로 C1~C4를 전부 통과한다.
게이트가 보증하는 것은 **"이 값이 그 인용문 안에 있고, 그 인용문이 그 PMID의
초록에 있다"**이지 **"이 값이 그 슬롯의 올바른 값이다"**가 아니다.

기준이 초록인 것도 한계다. 스크립트는 efetch로 받은 **초록만** 재조회한다 —
PMC 본문도 출판사 원문도 보지 않는다. 본문에만 있고 초록에 없는 숫자는
지어낸 값과 구별되지 않고 똑같이 탈락한다.

이해충돌도 같은 원칙이다. 팩은 진술 원문을 그대로 실을 뿐 "제조사 후원 연구"라고
**판정하지 않는다.** PubMed의 `GrantList`는 사실상 정부 과제만 색인되고 산업계
후원은 원문 Funding 섹션에만 있는 경우가 많아서, 그 라벨을 기계로 붙일 근거가
없기 때문이다. 진술이 없다는 것도 "이해충돌 없음"이 아니라 "받은 정보가 없음"이다.

결정론적 검사로 막을 수 있는 것은 여기까지다. 의미 판정까지 스크립트로 옮기려면
결국 LLM을 다시 불러야 하고, 그러면 게이트가 게이트가 아니게 된다.
**막을 수 있는 것만 기계로 막고, 남는 것은 사람에게 명시적으로 넘긴다** —
이 한계는 팩의 `warnings`에 매번 실려 나간다.

### 남긴 것을 어떻게 넘기는가 — `verdict`

`warnings`는 문장이고, 그걸 읽는 쪽은 LLM이다. **문장은 흘린다.** 종료 코드도
0과 2뿐이라 "폐기 슬롯 없음"과 "슬롯 절반 폐기"가 같은 0으로 수렴했다.
그래서 팩에 분기용 필드를 둔다.

| `verdict` | 뜻 | 종료 코드 |
|---|---|---|
| `pass` | 게이트가 걸 것을 다 걸었고 남은 것이 없다 | 0 |
| `review` | 사람이 봐야 할 것이 있다 (폐기 슬롯·제외 논문·철회·정오표·design 불일치·comparator 미상) | 0 |
| `block` | 팩을 신뢰할 수 없다 (수록 0편 / 제외가 수록 이상) | 2 |

`verdict_reasons`에 사유가 배열로 들어 있다. `kr-claims`의 리포트도 같은 두
필드를 갖는다 — 두 게이트가 같은 형태로 답하면 호출자가 한 가지 방법만 배우면 된다.

**`pass`는 "발행해도 된다"가 아니다.** 광고법 검토(P8)는 이 도구 밖이고 항상
미완이라 verdict에 넣지 않았다 — 넣으면 모든 팩이 영원히 `review`가 되어 필드가
신호를 잃는다. P8 경고는 verdict와 무관하게 매번 나간다.

## MVP 범위

포함: P1 정규화 / P2 근거스캔 / P3 숫자채굴 / P6 검증 / P6-1 식약처 대조

미포함: P4 반론논문 · P5 안전성 · P7 카피작성 · **P8 광고법 검사**

> P6-1은 `kr-claims`가 설치돼 있을 때만 돈다. 안 돌았으면 **국내 기준 대조를
> 하지 않았다는 사실이 출력에 남아야 한다** — 대조하지 않은 것이 통과로
> 읽히면 안 된다. 그리고 P6-1이 P8을 대신하지 않는다: 저쪽은 용량과 문구를
> 꺼내 놓을 뿐, 카피 표현의 적법성은 판정하지 않는다.

> ⚠️ P8이 없으므로 이 플러그인의 출력물을 그대로 발행하면 안 된다.
> 성분 설명과 제품 효능 표방의 경계는 사람이 검토해야 한다.
