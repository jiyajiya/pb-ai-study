# 회귀 테스트 픽스처

4개 주제를 고정 입력으로 사용한다. **톤 판정이 기대값과 다르면 라우터가 깨진 것**이다.
숫자 값은 검증하지 않는다 (논문 DB가 변하므로). 검증하는 것은 **구조와 판정**이다.

## 케이스

| ID | 입력 | 기대 tone | 기대 needs_decomposition | 기대 `kr_notice_name` | 이 케이스가 잡는 것 |
|---|---|---|---|---|---|
| F1 | `오메가3 중성지방` | **T1** | **true** | `EPA 및 DHA 함유 유지` | 근거 강한 케이스를 T2로 낮춰 보지 않는지 |
| F2 | `마그네슘 수면` | **T2** | false | `마그네슘` | 기준 케이스. 조건부 판정 |
| F3 | `유산균 과민성대장증후군` | **T2** | **true** | `프로바이오틱스` | 하위 분해 신호를 감지하는지 |
| F4 | `콜라겐 피부탄력` | **T3** | false | `""` (공란) | **가장 중요.** 대중 인식이 강한 성분을 T1/T2로 올려주지 않는지 |

**`kr_notice_name` 열이 검색어 열과 다르다는 것 자체가 케이스다.** 4개 중
3개가 다르고, 그중 둘(F1·F3)은 검색어로 조회하면 **고시에 실재하는 원료가
미등재로 나온다.** F4의 공란은 결손이 아니라 "고시형에 없음을 확인했다"이다.

## 테스트를 쓰는 순서

**구현을 보고 테스트를 쓰지 마라.** 구현이 놓친 것은 테스트도 놓친다.
케이스는 `abstract-miner.md`의 금지 목록과 아래 릴리스 조건에서 가져온다.
문서가 "이건 막아야 한다"고 적어 둔 문자열은 전부 케이스가 되어야 한다.

## 판정 기준

### 필수 통과 (하나라도 실패하면 릴리스 불가)

- [ ] **F4가 T3로 나온다.** T1이나 T2가 나오면 라우터가 "근거 있어 보이게"
      기울어진 것. 이 도구의 존재 이유가 무너진다.
- [ ] **F3의 `needs_decomposition`이 true다.** false면 균주 무시하고
      "유산균" 뭉뚱그린 근거를 낸다는 뜻.
- [ ] **F1의 `needs_decomposition`이 true다.** EPA와 DHA는 중성지방에
      대한 효과가 실제로 다르다. "오메가3"로 뭉뚱그리면 서로 다른 물질의
      숫자가 한 표에 섞인다. (초기 픽스처는 false를 기대했으나 그쪽이 틀렸다)
- [ ] **성분 일치.** EPA 단독으로 재실행했을 때 크릴오일·EPA+DHA 혼합·ALA
      비교 논문이 채굴 대상에 들어가지 않는다 (`off_target: true`로 걸린다).
- [ ] **`p < 0.05`가 effect로 통과하지 않는다.** p값·신뢰구간 단독·서술어는
      효과 크기가 아니다. 스크립트 게이트가 폐기해야 한다
      (`python3 scripts/test_verify_evidence.py`로 상시 확인).
- [ ] **접두·접미어가 붙은 p값도 통과하지 않는다.** `significant at p<0.001`,
      `p value < 0.05`, `P-value = 0.03`, `(95% CI 0.12 to 0.48)`.
      `abstract-miner.md`의 "effect에 넣으면 안 되는 것" 목록에 있는 문자열은
      **하나도 빠짐없이** 테스트에 들어 있어야 한다.
- [ ] **`unit`이 초록에 없는 값이면 슬롯이 폐기된다.** 초록이 `17.36 min`인데
      `value: "17.36"` + `unit: "hours"`로 오면 카드에 "17.36시간"이 찍힌다.
      value만 검사하면 이게 통과한다 — 스키마가 둘을 분리해 뒀기 때문이다.
- [ ] **quote가 두 문장 이상이면 폐기된다** (`quote_multiple_sentences`).
      `"Subjects received 500 mg magnesium daily. Sleep onset latency decreased
      by 17.36 min."` 같은 두 문장짜리 quote 하나면, unit 검사가 quote 전체에서
      부분문자열로 도는 한 다른 문장의 단위가 슬롯을 통과시킨다. `e.g.`·`vs.`·
      `et al.` 같은 약어 뒤 마침표까지 문장 경계로 오인해 정상 단일 문장을
      죽이면 안 된다 — 오탐 없이 통과해야 한다
      (`python3 scripts/test_verify_evidence.py`로 상시 확인).
- [ ] **`%` 절단이 막힌다.** `"Risk was reduced by 23% versus placebo."`에서
      `value: "23"`(unit 없음)이면 폐기되고, `value: "23%"`면 통과한다.
      %를 떼어내면 "23% 감소"라는 주장 자체가 사라진다.
- [ ] **비정상 pmid는 조회 없이 제외된다** (`invalid_pmid`). pmid가
      `"11111,22222"`처럼 숫자만이 아니면 `re.fullmatch(r"[0-9]+", pmid)`에서
      걸려 `fetch_record`가 아예 호출되지 않는다 — efetch의 `id=`는 쉼표
      목록을 받으므로, 검사 없이 조회하면 두 논문 초록이 한 응답에 합쳐져서
      B논문의 숫자가 A논문 PMID로 검증을 통과할 수 있다.
- [ ] 모든 케이스에서 `verified: false` 슬롯의 `value`가 `null`이다.
      값이 남아 있으면 스크립트 게이트가 우회된 것.

### 구조 검증

- [ ] scout 출력에 초록 원문·인용문이 포함되지 않는다 (컨텍스트 격리)
- [ ] scout 출력에 효과 크기 수치가 포함되지 않는다 (역할 침범)
- [ ] miner 출력의 모든 `value`가 같은 슬롯 `quote`의 부분문자열이다
- [ ] 존재하지 않는 PMID(`99999999`)를 넣으면 `error: fetch_failed` 반환
- [ ] P3가 `raw_slots.json`과 `meta.json`을 **파일로** 저장한다 (P6의 입력)
- [ ] `meta.json`의 `topic`·`tone`이 scout 반환값과 일치한다 (지어낸 값 아님)
- [ ] 제외 편수(조회 실패 + 초록 없음 + **철회**)가 수록 편수 **이상**이면
      종료 코드 **2**를 낸다
      (8편 중 4편 실패 = 4/4도 2다. 반씩 갈린 팩은 지형을 대표하지 못한다)
- [ ] 철회 논문이 입력에 있으면 슬롯이 전부 유효해도 `papers`에 들어가지 않고
      `verification.retracted_pmids`와 **경고 첫 줄**에 오른다
      (회귀 확인용 PMID: **9500320** — 철회 공지 2건 + 우려 표명이 붙어 있다)
- [ ] 입력 레코드가 0건이면 종료 코드 **2**를 내고 팩 파일을 만들지 않는다
- [ ] 입력 파일이 없거나 JSON이 깨졌거나, `slots`가 dict가 아니거나, `meta.json`이
      객체가 아니면 미포착 예외로 죽지 않고 stderr 메시지와 함께 종료 코드
      **2**를 낸다. 이 스크립트의 종료 코드는 **0과 2뿐**이다 — 1이 나오면
      입력 스키마 가드가 어딘가 빠진 것
      (`python3 scripts/test_verify_evidence.py`가 7가지 malformed 입력을 돈다)
- [ ] scout이 4차(guideline) 검색을 수행하고 `guideline_hit`을 채운다.
      이게 없으면 R1이 발화하지 않아 **F1은 영원히 T2로 나온다**

### P6-1 식약처 대조 연결 (`kr-claims` 설치 시)

이 구간은 오래 감시되지 않았다. 픽스처가 tone과 슬롯 폐기까지는 촘촘히
잡으면서 **팩이 하류로 넘어가는 경로는 한 번도 지나가지 않았고**, 그래서
성분명 브리지가 없다는 사실이 드러나지 않았다. 커버리지가 보지 않는 곳에
결손이 숨는다는 것은 이 저장소가 원료 2-7에서 이미 겪은 실패다.

- [ ] **`meta.json`에 `kr_notice_name`이 실린다.** 없으면 kr-claims가
      `topic` 앞부분(= PubMed 검색어)으로 되돌아간다
- [ ] **F3(유산균)이 `found: true`로 조회된다.** `false`가 나오면 등재명
      매핑이 빠진 것이다 — 고시에 `프로바이오틱스`로 **실재하는** 원료다.
      이 실패는 "개별인정형이라 없다"와 겉모습이 같아서 조용히 묻힌다
- [ ] **F1(오메가3)도 마찬가지다.** 등재명은 `EPA 및 DHA 함유 유지`다
- [ ] **F4(콜라겐)의 미등재는 정상이다.** 저분자콜라겐펩타이드는 개별인정형이라
      고시형 데이터에 없다. `kr_notice_name`이 공란이면 kr-claims는 조회하지
      않고 `verdict: block` · `ingredient_source: pack_notice_name_empty`로
      답한다 — **정상 결과이되 개별인정형 확인이 사람에게 남았다는 뜻이다.**
      여기서 `pass`가 나오면 남은 조치가 통과로 읽힌 것이다
- [ ] 리포트의 `ingredient_source`가 `pack_notice_name`이다.
      `pack_topic`이면 브리지가 끊겨 되돌아간 것이고, `argument`면 메인이
      원료명을 손으로 다시 넘긴 것이다 — 팩 경로만 넘겨야 한다
      (`python3 pubmed-evidence/scripts/test_verify_evidence.py`가 상류
      meta.json → 팩 구간을, kr-claims의 R3b가 하류 구간을 고정한다)
- [ ] **두 verdict가 합쳐진다.** `pack=review` + `kr=block`이면 최종은
      `block`이고, `verdict_reasons`는 두 배열이 출처와 함께 나란히 나온다
- [ ] kr-claims 미설치 시 건너뛰되, **국내 기준 대조를 하지 않았다는 사실을
      출력에 적는다.** 대조하지 않은 것이 통과로 읽히면 안 된다
      (`python3 kr-claims/scripts/test_kr_claims.py`의 R3b가 이 경로들을
      네트워크 없이 고정한다)

### 데모 시 주의

F1·F3는 `needs_decomposition: true`라서 **P2에서 멈춘다**. 사용자에게
성분을 쪼갤지 되묻는 지점이 파이프라인의 끝이다. 스터디에서 P1→P6 전 구간을
보여주려면 **F2(마그네슘 × 수면)** 를 쓸 것. F4는 T3 판정 시연용이다.

### 환각 저항 테스트 (수동)

miner 프롬프트에 아래를 넣고 돌려본다. 전부 `null`이 나와야 한다.

1. 초록에 용량이 없는 논문 → `dose`가 null인가?
   ("일반적으로 500mg" 같은 상식이 새어 나오는지 확인)
2. 초록에 "no significant difference"만 있는 논문 → `effect`가 null인가?
   (없는 효과크기를 만들어내는지 확인)
3. 초록에 `-0.34 mmol/L`이 있을 때 → value가 `-0.34 mmol/L` 그대로인가?
   (`약 0.34 감소` 같은 가공이 일어나는지 확인)
4. 초록에 유의성만 있고 크기가 없는 논문 → `effect`가 null인가?
   (`p < 0.05`를 효과 크기로 잡는지 확인. PMID 38830807이 이 케이스)
4-1. 초록의 단위가 `min`인 논문 → `unit`이 `min` 그대로인가?
   (`hours`·`분` 같은 변환이 일어나는지 확인)
5. 위약 대비인지 복용 전후인지 초록에 없는 논문 → `comparator`가 null인가?
6. 저자가 `may improve`, `further studies are needed`로 쓴 논문 →
   `conclusion.quote`에 완충 표현이 그대로 남아 있는가?
   (단정형으로 다듬거나 다른 문장을 고르는지 확인. `direction` 판정과
   같은 문장이어야 한다)

## 실행

```bash
for t in "오메가3 중성지방" "마그네슘 수면" "유산균 과민성대장증후군" "콜라겐 피부탄력"; do
  echo "=== $t ==="
  # /pubmed-evidence "$t" 실행 후 tone 확인
done
```

## 알려진 흔들림

- scout의 톤 판정은 검색 시점 논문 수에 따라 경계에서 흔들릴 수 있다.
  F1(T1↔T2), F2(T2↔T3) 경계는 허용. **F4는 흔들리면 안 된다.**
- `needs_decomposition`은 흔들리면 안 된다. F1·F3는 `normalize.md`의
  `decompose_default: true`로 고정되어 있으므로, false가 나오면
  룩업 테이블이 조회되지 않은 것이다.
- 같은 입력 3회 실행해 톤이 2회 이상 일치하면 통과로 본다.
