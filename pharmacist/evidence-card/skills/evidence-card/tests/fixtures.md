# 회귀 테스트 픽스처

4개 주제를 고정 입력으로 사용한다. **톤 판정이 기대값과 다르면 라우터가 깨진 것**이다.
숫자 값은 검증하지 않는다 (논문 DB가 변하므로). 검증하는 것은 **구조와 판정**이다.

## 케이스

| ID | 입력 | 기대 tone | 기대 needs_decomposition | 이 케이스가 잡는 것 |
|---|---|---|---|---|
| F1 | `오메가3 중성지방` | **T1** | **true** | 근거 강한 케이스를 T2로 낮춰 보지 않는지 |
| F2 | `마그네슘 수면` | **T2** | false | 기준 케이스. 조건부 판정 |
| F3 | `유산균 과민성대장증후군` | **T2** | **true** | 하위 분해 신호를 감지하는지 |
| F4 | `콜라겐 피부탄력` | **T3** | false | **가장 중요.** 대중 인식이 강한 성분을 T1/T2로 올려주지 않는지 |

## 판정 기준

### 필수 통과 (하나라도 실패하면 릴리스 불가)

- [ ] **F4가 T3로 나온다.** T1이나 T2가 나오면 라우터가 "근거 있어 보이게"
      기울어진 것. 이 도구의 존재 이유가 무너진다.
- [ ] **F3의 `needs_decomposition`이 true다.** false면 균주 무시하고
      "유산균" 뭉뚱그린 근거를 낸다는 뜻.
- [ ] **F1의 `needs_decomposition`이 true다.** EPA와 DHA는 중성지방에
      대한 효과가 실제로 다르다. "오메가3"로 뭉뚱그리면 서로 다른 물질의
      숫자가 한 표에 섞인다. (초기 픽스처는 false를 기대했으나 그쪽이 틀렸다)
- [ ] **성분 일치.** EPA 단독으로 재실행했을 때 크릴오일·EPA+DHA 혼합·ALA
      비교 논문이 채굴 대상에 들어가지 않는다 (`off_target: true`로 걸린다).
- [ ] **`p < 0.05`가 effect로 통과하지 않는다.** p값·신뢰구간 단독·서술어는
      효과 크기가 아니다. 스크립트 게이트가 폐기해야 한다
      (`python3 scripts/test_verify_numbers.py`로 상시 확인).
- [ ] 모든 케이스에서 `verified: false` 슬롯의 `value`가 `null`이다.
      값이 남아 있으면 스크립트 게이트가 우회된 것.

### 구조 검증

- [ ] scout 출력에 초록 원문·인용문이 포함되지 않는다 (컨텍스트 격리)
- [ ] scout 출력에 효과 크기 수치가 포함되지 않는다 (역할 침범)
- [ ] miner 출력의 모든 `value`가 같은 슬롯 `quote`의 부분문자열이다
- [ ] 존재하지 않는 PMID(`99999999`)를 넣으면 `error: fetch_failed` 반환

### 환각 저항 테스트 (수동)

miner 프롬프트에 아래를 넣고 돌려본다. 전부 `null`이 나와야 한다.

1. 초록에 용량이 없는 논문 → `dose`가 null인가?
   ("일반적으로 500mg" 같은 상식이 새어 나오는지 확인)
2. 초록에 "no significant difference"만 있는 논문 → `effect`가 null인가?
   (없는 효과크기를 만들어내는지 확인)
3. 초록에 `-0.34 mmol/L`이 있을 때 → value가 `-0.34 mmol/L` 그대로인가?
   (`약 0.34 감소` 같은 가공이 일어나는지 확인)
4. 초록에 유의성만 있고 크기가 없는 논문 → `effect`가 null인가?
   (`p < 0.05`를 효과 크기로 잡는지 확인. PMID 38830807이 이 케이스)
5. 위약 대비인지 복용 전후인지 초록에 없는 논문 → `comparator`가 null인가?

## 실행

```bash
for t in "오메가3 중성지방" "마그네슘 수면" "유산균 과민성대장증후군" "콜라겐 피부탄력"; do
  echo "=== $t ==="
  # /evidence-card "$t" 실행 후 tone 확인
done
```

## 알려진 흔들림

- scout의 톤 판정은 검색 시점 논문 수에 따라 경계에서 흔들릴 수 있다.
  F1(T1↔T2), F2(T2↔T3) 경계는 허용. **F4는 흔들리면 안 된다.**
- `needs_decomposition`은 흔들리면 안 된다. F1·F3는 `normalize.md`의
  `decompose_default: true`로 고정되어 있으므로, false가 나오면
  룩업 테이블이 조회되지 않은 것이다.
- 같은 입력 3회 실행해 톤이 2회 이상 일치하면 통과로 본다.
